# Lessons

## アイコンを横に並べるとき、CSS の箱だけ揃えても足りない

**指摘（2026-08-14）:** ヘッダーの GitHub アイコンとハンバーガーメニューがズレて見える。

**何を見落としたか:**

1. **SVG の viewBox 内で絵が偏っていた。** `Hamburger` は `viewBox="0 0 24 24"` なのに
   実際の描画は x:4.5〜19.5 / y:4.5〜17.45 にしかなく、絵の中心は y≈11.0（viewBox の中心は 12）。
   CSS の箱を完璧に中央揃えしても、絵そのものが箱の中で上に寄る。
   さらに縦方向に viewBox の 54% しか使っていないため、viewBox の 92% を使う GitHub アイコンと
   同じ `width` を指定しても小さく見える。
2. **箱とアイコンのサイズがちぐはぐだった。** `.link` を 40px にしたまま、中の SVG は 48px。
   4px はみ出し、ホバーの背景がアイコンより小さくなっていた。
3. **箱のサイズが左右で違った**（GitHub 40px / ハンバーガー 64px）。
   `align-items: center` で中心は揃うが、間隔と見た目の重さが揃わない。

**2回目の指摘（同日）:** 「これではない、まだズレている」。
1回目の修正で viewBox を「絵に外接する正方形」に手計算で直したが、
それでもバーガーの描画高さは 38.7px、GitHub は 44.2px と 5.5px の差が残っていた。
中心は合っていても**サイズが揃っていない**とズレて見える。

→ viewBox を**絵の実バウンディングボックスそのもの**（`4.4 4 15.2 13.7`）にした。
こうすると `preserveAspectRatio` のデフォルト `xMidYMid meet` が
CSS で与えた箱の中央に自動で収めるので、位置合わせに手計算が一切要らなくなる。
結果: 両方とも箱の中心からのズレ 0.00px、描画高さ 44.2px / 43.3px。

**次からのルール:**

- **viewBox は絵の実バウンディングボックスに合わせる。** 中心を手計算で合わせにいかない。
  実 bbox にしておけば `preserveAspectRatio` のデフォルトが中央寄せをやってくれるし、
  隣のアイコンと同じ CSS サイズを指定するだけで描画サイズも揃う。
- **bbox は目視や手計算でなくパースして出す。** ベジェの制御点は曲線の実際の通過点と違うし、
  stroke 幅・linecap の分だけ外側に広がる（今回はレタスの `strokeWidth 1.2` が最外だった）。
  `tasks/` に置いたパス解析スクリプトの方式で数値を出してから直す。
- **「中心が合っている」だけでは揃って見えない。描画サイズも揃える。**
  1回目の修正は中心のズレを 2.59px → 0.42px にしたが、サイズ差 5.5px が残って再指摘された。
- 並べるアイコンは**同じ親の flex 行に入れ、箱を同一サイズの正方形にする**。
  親を分けたまま `margin-left: auto` などで並べると、箱サイズの違いに気づきにくい。
- アイコンのレンダリングサイズを変えたら、**囲みの箱・ホバー領域・タップ判定も必ず一緒に更新する**。
- 「視覚的に揃っているか」はブラウザで確認できないときほど、
  **座標を計算して数値で確認する**（今回は絵の中心 y と箱の中心 y を突き合わせて検証した）。

## 絶対配置の擬似要素は通常フローの兄弟より前面に描く（2026-08-15）

**指摘:** Historys のレールが日付ピルの上に重なっていた。

**原因:** `.item::before`（`position: absolute`）はペイント順で通常フローの `.marker` より後 = 前面。ピルの背景を不透明にしても、線が上から描かれるので隠れない。

**How to apply:** 絶対配置の背景装飾（レール・下線・ブロブ）を敷いたら、前に出したい通常フロー要素に `position: relative; z-index: 1` を必ず付ける。`z-index: -1` で装飾を後ろに送るのは、祖先の背景に埋もれるので使わない。

## スクリーンショットで検証するときの落とし穴（2026-08-15）

- `--headless --window-size=390,x` は macOS の最小ウィンドウ幅（500px）に切り上げられる。狭幅の検証は CDP の `Emulation.setDeviceMetricsOverride` を使う。
- 配色は `--blink-settings=preferredColorScheme` より `Emulation.setEmulatedMedia` の方が確実。`--user-data-dir` を使い回すと既存インスタンスに転送されてフラグが効かないことがある。
- `sips --cropOffset 0 0` はオフセット無指定と同じ扱いになり中央クロップされる。上端を切るなら `1 0`。
- CDP スクリーンショットは `deviceScaleFactor: 2` なので、CSS px でクロップしたいなら先に 1x へリサイズする。

## 「見た目を良くして」は装飾だけでなく壊れている箇所を疑う（2026-08-15）

Historys は日付が円からはみ出し、description が `height` 固定 + `overflow: hidden` で切れ、空リンクが描画されていた。見た目の相談を受けたら、まず既存の表示バグを洗い出してから装飾に入る。

## 依頼のトーンを読む（2026-08-15）

Hobbies は最初「サイトの既存トーンに合わせた上品なカード」で作ったが、求められていたのは「趣味らしくポップ」。趣味・ギャラリーなど遊びのあるセクションは、他セクションと同じ抑制的なトーンに揃えるのが正解とは限らない。迷ったら方向性（上品 / ポップ）を先に確認する。

## 「手元で崩れる/動かない」はユーザーのブラウザ状態を先に見る（2026-09-29）

**指摘:** 「about 画面に飛べなくね？」「History や Hobbies の UI 崩れていますが？」

**原因:** ユーザーの Chrome の `localhost:3000` に別プロジェクト（yoyaku）の Service Worker が残っており、`/_next/static/chunks/*.css` を旧版のキャッシュで返していた。Turbopack の dev チャンク名は内容ハッシュを含まないので、HTML だけ新しく CSS が古い状態になる。

**反省:** ヘッドレス Chrome（まっさらなプロファイル）と curl で再現しないことを確かめただけで「再現しない」と返し、ユーザーの環境を見に行くのが遅れた。

**How to apply:** こちらで再現しない表示崩れ・遷移不良は、Claude in Chrome でユーザーの Chrome に新規タブを開いて確認する。`getComputedStyle` で想定のスタイルが当たっているか → `fetch(css, {cache:'no-store'})` の中身 → `navigator.serviceWorker.getRegistrations()` / `caches.keys()` の順に見る。

## ignore したディレクトリは、それを追跡しているブランチをマージすると黙って上書きされる（2026-09-30）

**経緯:** `tasks/` をローカルブランチで `.gitignore` に入れた一方、main では別セッションが `tasks/` をコミットしていた。`git merge origin/main` で、ignore 済みのローカル `tasks/*.md` が警告なしに main 版で置き換わった（git は ignored ファイルを「消してよいもの」とみなす）。

**How to apply:** ignore 対象にローカルだけの大事なファイルがあるときは、マージ／チェックアウトの前に `git ls-tree -r --name-only <相手ブランチ> <dir>` で相手側が追跡していないか確かめ、していればファイルを退避してからマージする。
